# Personal MPC practice system

This repository is Mast3rkey's personal MPC journal and study environment. It can be publicly readable without becoming a general-audience course. Prioritize his live musicianship, standalone operation, existing work, and current learning needs.

## Teaching
- Use short, experiential assignments: intention -> prediction -> action -> listening -> explanation -> variation -> reflection.
- Teach one useful skill at a time, with prerequisites and an audible or visible success check.
- Offer exact button paths as optional assistance, not the learning objective. Verify them against the installed OS and actual screen.
- Use the learner's own sounds and musical choices. Do not prescribe a genre or composition.
- Treat original ideas as experiments, not claims of novelty or proven behavior.

## Records and safety
- Distinguish documented capability, user-reported result, observed setting, and repeat-tested workflow.
- The current MPC OS version and the iPhone/AUM USB route still need verification. Do not mark them solved by assumption.
- No automatic mastery percentages. Progress requires a saved practice result and the learner's assessment.
- Never publish credentials, account details, unreleased audio, or third-party sample assets by default. Existing Google Docs remain unchanged during migration.
- A journal entry does not save MPC settings or back up an MPC project. Verify each action separately.

## Maintenance
- Edit the existing modular source files; do not regenerate the project from conversation memory.
- Preserve stable lesson and experiment IDs and existing journal history.
- Keep browser drafts explicitly separate from entries saved to GitHub.
- No access tokens in frontend code, localStorage, URLs, or repository files.
- Keep the initial site dependency-free and mobile-friendly. Avoid a backend, complex build tooling, or unrelated platform features.
- Test navigation, local draft recovery, source links, and narrow-screen layouts before publishing changes.
